# Security rules — FinalProjectTecEmergentes

> Governing file. Every change MUST comply with it. Every rule is verifiable.
> Framework: Colombian Law 1581 of 2012 (personal data protection) and Decree 1377 of 2013. Requirements: course
> guide `CL12_26102026.pdf` (anonymization, trusted joblib files, version alignment) and `docs/analysis.md`.

## 1. Personal and sensitive data

Comments can contain names of people. The project stores no database and encrypts nothing at rest because the API
persists no user input (SEC-01, SEC-03); the versioned dataset is synthetic and provided by the course.

| ID | Rule |
|---|---|
| SEC-01 | Uploaded CSV content MUST be processed in memory only. `/predict-batch` MUST accept the CSV as a raw `text/csv` request body (no multipart form, so no temporary file is created). The API MUST NOT write comment text to disk. |
| SEC-02 | Every comment text the API returns in batch rows, quotes, summaries or course reports, and every quote written to `models/*/report.json`, MUST pass through the `Anonymizer` port first. It MUST mask person entities, emails, phone numbers (7 or more digits) and ids (6 to 10 digits). If the anonymizer fails to load, the API MUST refuse to start. Only `/predict` returns the caller's own text unmasked. |
| SEC-03 | Retention: the API MUST NOT persist comments, uploads, predictions or review decisions. In-memory state (latency buffer, decision counters, last drift report) is lost on restart. Review decisions live only in the browser's `localStorage`. |
| SEC-04 | `os.umask(0o077)` MUST be the first instruction of `api/main.py` and of the `main()` function of every `ml` command-line entry point. Directories created under `data/`, `models/`, `reports/` and `gold/` MUST be 0700; files 0600. The container MUST run with the host user's UID (`user: "${UID:-1000}"` in `docker-compose.yml`). |
| SEC-05 | Logs MUST go to stdout only; no log file is created. Logs MUST NOT contain comment text, upload contents or file names: code MUST use `redact()` and every handler MUST have the `RedactingFilter`, both from `api/domain/safety.py`. Logs hold request id, route, row counts, text lengths, timings and model version only. |
| SEC-06 | The name and client path of an uploaded file MUST NOT be stored or logged; only the SHA-256 of the request body appears in the drift report. |
| SEC-07 | The review-queue CSV export is built in the browser and MUST prefix with `'` every cell that starts with `=`, `+`, `-`, `@`, a tab or a carriage return. `ml` writes only under `data/`, `models/`, `reports/` and `gold/`. |

## 2. External development services and test data

| ID | Rule |
|---|---|
| SEC-08 | External development services (including AI assistants) receive ONLY documentation and code. Real student comments, logs, uploads and model bundles MUST NOT be sent. The course-provided synthetic `Dataset/` is already part of the repository. |
| SEC-09 | Every fixture and example MUST be synthetic, generated by code or hand-written. Real data MUST NOT be versioned. Single exception (decision 2026-11-05): `Dataset/`, the synthetic dataset provided by the course, is versioned and read by integration tests. |
| SEC-10 | These paths MUST be in `.gitignore`: `data/`, `reports/`, `models/v*/bundle.joblib`, `.venv/`, `__pycache__/`, `.env`. |

## 3. Inputs and paths

| ID | Rule |
|---|---|
| SEC-11 | Every input file read from disk by `ml` MUST: have the extension `.csv` (compared in lowercase), be a regular file (not a symlink, not a device), weigh ≤ 2 MB, be inside `Dataset/` or `gold/` after `Path.resolve(strict=True)` and parse with pandas. Every HTTP input MUST: have text of 1 to 2,000 characters after stripping; have a CSV body ≤ 2 MB (checked on `Content-Length` and while reading), ≤ 5,000 rows, strict UTF-8 with optional BOM and the required columns; otherwise the API returns a 4xx error. |
| SEC-12 | Every output path MUST be resolved with `resolve_within(base, candidate)` from `api/domain/safety.py`; if it escapes its base → `UnsafePathError`. Generated file names MUST NOT derive from input data (versions are `vNNN` generated by `ml.artifact`). |
| SEC-13 | Configuration and reports MUST be read with the `json` module. `yaml.load`, `pickle`, `eval`, `exec` and `shell=True` MUST NOT be used. |

## 4. Database

Not applicable in this project: there is no database; nothing is persisted at runtime (SEC-03).

## 5. Models and binary artifacts

| ID | Rule |
|---|---|
| SEC-14 | Model bundles MUST be loaded only from `models/` after: resolving the path inside `models/`, rejecting symlinks, verifying the SHA-256 of `bundle.joblib` against `models/vNNN/manifest.json` and checking that the installed versions of scikit-learn, numpy, joblib and mapie equal the manifest, on every load. Mismatch → `ModelIntegrityError` and the process exits. `joblib.load` MUST appear only in `api/adapters/model_store.py` and `ml/artifact.py`. |
| SEC-15 | Deserialization MUST NOT use `pickle` or `torch.load`. Exception: `joblib.load` of the project's own bundles verified by SEC-14. Embedding weights are loaded only by sentence-transformers from the local cache at the revision recorded in the manifest. |

## 6. Network

| ID | Rule |
|---|---|
| SEC-16 | In normal operation there MUST NOT be network calls, except `python -m ml.representations --download` and the Docker image build. `api/main.py` MUST set `HF_HUB_OFFLINE=1` and `TRANSFORMERS_OFFLINE=1` before importing any model library; the Dockerfile sets both. The server MUST listen only on `127.0.0.1`; inside the container it binds `0.0.0.0` only because `docker-compose.yml` publishes `127.0.0.1:8000:8000`. |
| SEC-17 | The embedding model MUST be downloaded by name at a pinned commit `revision` recorded in the manifest. `es_core_news_sm` MUST be installed from an `https://` URL pinned in `requirements.txt`. The project uses no API keys. |

## 7. Dependencies and secrets

| ID | Rule |
|---|---|
| SEC-18 | All dependencies, direct and transitive, MUST be pinned to an exact version (`==`) in the versioned `requirements.txt` and `requirements-dev.txt`. Installation MUST use them (`pip install -r requirements.txt -r requirements-dev.txt`). |
| SEC-19 | `pip-audit -r requirements.txt` MUST run in the `Gate` and report no unjustified vulnerabilities (exceptions are documented in `docs/adr/`). Documented exception: `torch==2.15.0+cpu` is not auditable by `pip-audit` (ADR-005); its advisories are checked by hand at each pin change. |
| SEC-20 | There MUST NOT be secrets in the code or in the repository. Developer secrets, if any appear, live in `.env` (in `.gitignore`). |
| SEC-21 | Error messages returned to clients MUST NOT include comment text, file paths, stack traces or library messages. A 500 error returns a generic message and the request id; the traceback goes to the log through `RedactingFilter`. |
| SEC-22 | Every HTTP response of the service (API routes and static files) MUST carry these headers, set by the `request_context` middleware of `api/main.py`: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin` and `Cache-Control: no-store`. Files in `web/` MUST NOT use `innerHTML`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval(`, `new Function`, `setAttribute("style"`, an inline `<script>`, a `style` attribute or an inline `on*` handler, and MUST NOT request any URL outside `'self'`. |

## 8. Security review checklist (apply to every implementation)

One box per `SEC-NN` rule, in the same order, with the exact command when one exists.

- [ ] Does `/predict-batch` read a raw `text/csv` body and write nothing to disk? `grep -rn "UploadFile\|NamedTemporaryFile\|SpooledTemporaryFile" api/` empty (SEC-01)
- [ ] Does every returned or stored quote, summary and batch text go through `Anonymizer`, and does startup fail without it? (SEC-02)
- [ ] Does the API persist anything (files, database, cache of inputs)? (SEC-03)
- [ ] Is `os.umask(0o077)` the first instruction of every entry point? `grep -rn "os.umask(0o077)" api/main.py ml/` (SEC-04)
- [ ] Is there any log line with comment text, upload content or file name, or any file handler? `grep -rn "FileHandler\|print(" api/` empty (SEC-05)
- [ ] Is the upload file name or path stored or logged? (SEC-06)
- [ ] Does the CSV export prefix dangerous cells with `'`? Does `ml` write outside its four directories? (SEC-07)
- [ ] Was any real comment, log, upload or bundle sent to an external service? (SEC-08)
- [ ] Are fixtures synthetic, with no real data in the diff outside `Dataset/`? (SEC-09)
- [ ] Does `.gitignore` still cover `data/`, `reports/`, `models/v*/bundle.joblib`, `.venv/`, `__pycache__/`, `.env`? (SEC-10)
- [ ] Are file and HTTP inputs validated (extension, regular file, size, location, rows, UTF-8, columns, text length)? (SEC-11)
- [ ] Does every output path go through `resolve_within` from `api/domain/safety.py`? (SEC-12)
- [ ] Is `yaml.load`, `pickle`, `eval`, `exec` or `shell=True` used? `grep -rnE "yaml\.load|pickle|eval\(|exec\(|shell=True" api/ ml/ scripts/` empty (SEC-13)
- [ ] Is `joblib.load` only in the two allowed files, after hash and version checks? `grep -rn "joblib.load" api/ ml/` lists only `api/adapters/model_store.py` and `ml/artifact.py` (SEC-14)
- [ ] Is `torch.load` or `pickle` used for deserialization? `grep -rnE "torch\.load|pickle\.load" api/ ml/` empty (SEC-15)
- [ ] Are offline flags set before model imports, and does the server bind only to `127.0.0.1` on the host? (SEC-16)
- [ ] Is the embedding revision pinned in the manifest and the spaCy model URL pinned in `requirements.txt`? (SEC-17)
- [ ] Are versions pinned with `==` in both requirements files? `grep -vnE "^\s*(#|$|.*==|.*@ https://|--extra-index-url https://download\.pytorch\.org/whl/cpu$)" requirements.txt requirements-dev.txt` empty (SEC-18)
- [ ] Does `pip-audit -r requirements.txt` pass inside the `Gate`? (SEC-19)
- [ ] Is there any secret in code or repository? (SEC-20)
- [ ] Can an error response leak comment text, paths or a traceback? (SEC-21)
- [ ] Does every response carry the SEC-22 headers, and is `web/` free of HTML-string sinks, inline script and inline style? `grep -rnE "innerHTML|outerHTML|insertAdjacentHTML|document\.write|eval\(|new Function|setAttribute\(.style|<script>|style=| on[a-z]+=" web/` empty (SEC-22)
